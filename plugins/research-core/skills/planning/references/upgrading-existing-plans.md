# Improve an existing plan only where useful

Read this when `planning` encounters an existing plan. Structural cleanup does not grant launch,
scientific acceptance, task closure, or a coordination-model change.

## Choose the smallest action

Read the declaration, root registry, current authority, linked evidence, and relevant history.

- Leave completed, dormant, cancelled, superseded, or accurate records alone by default.
- Add a missing dependency, acceptance pointer, or current-focus clarification without reformatting
  the rest when that solves the discovery problem.
- Improve the current phase and handoff when active work cannot be launched or reviewed from the
  existing record.
- Explain contradictory authority, unsupported completion, or ambiguous scientific state before
  moving prose in a way that could make one claim look authoritative.
- In GitHub coordination, keep executable task state in Issues. In Hybrid, preserve programme
  decisions/acceptance in the plan and link Issues without mirroring task state.

## Preserve meaning

Before editing, identify accepted scope, rationale, canonical active files, evidence/provenance,
limitations, unresolved work, review progress, and downstream restrictions. Keep each fact in its
declared authoritative home.

An old status word is historical evidence, not automatic proof of current acceptance or invalidity.
Preserve its original meaning and mark acceptance unknown if the record cannot establish it. Do not
impose a new lifecycle vocabulary.

Keep useful anchors stable. When moving necessary detail, update real consumers and leave an
intelligible pointer. Preserve unique rationale, warnings, and influential exploration. Do not
normalize the whole project, rewrite historical records to look current, or replace a manifest,
validator, generated record, or human decision with plan prose.

## Check the result

Compare before and after for accepted claims, limitations, lineage, pending decisions,
dependencies, review state, and downstream permission. Check changed links and the root discovery
route. Report what was preserved, clarified, left unknown, and intentionally untouched.

`done` may reconcile affected current records without redesigning the plan. `audit-project` may
report semantic drift without migrating it. Legacy plans remain usable; unavailable fields remain
Unknown rather than being invented to fit a template.
